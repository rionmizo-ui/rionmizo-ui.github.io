## 1. ゲームの芯

- 一匹の和金を、ゲージ25目盛りぶん世話して育てる。縦画面の携帯ゲーム機（将来 Arduino 系）を想定し、まずブラウザ（Windows）で試す。
- ごほうびは「どう育てたかで変わる、おかしな最期」を見ること。途中で突然死もする。最期は図鑑（36枠）に集まる。
- 1匹あたり3〜5分が目標。死んだら泡で画面をおおって水槽をリセットし、次の魚（何匹目かを数える）。
- 雰囲気：かわいいカートゥーン調のドット絵 × とぼけたブラックユーモア。説明なしで魚の反応から状態が読めること。

## 2. 画面と操作

- 内部解像度 **160×240**（縦2:3）、整数倍に拡大表示（`image-rendering: pixelated`）。
- 主な座標：水面 y=22、砂 y≈212〜222、画面下の帯 y=223〜238。
- 画面のパーツ：
  - 左の縦ゲージ（育成、25目盛り）：x=4..11, y=30..140
  - 右上のアイコン枠（予約・回収の網）：x=136..155, y=4..23
  - 左上の3つのランプ（餌・掃除・ふれあい）：点灯＝コンボの進み、オレンジ枠＝魚がいま欲しい世話。右に「N匹目」
  - 画面下の帯：空腹バー（食べると0、8割超で赤点滅）、ストレスバー（緑→黄→赤、75以上で点滅）、汚れ4マス（3以上で点滅）
- ボタン：本体下に **餌・掃除・ふれあい**、右上に **網**。キーボードは 1/2/3（Z/X/C）＝餌・掃除・ふれあい、4/V/スペース＝網。右上に「♪ BGM」のオン・オフ。
- 入力：1押し1操作。世話の途中に押した世話は1枠だけ予約し、後から押したもので上書き。網は予約しない。餌だけは食べている最中でも追加できる。

## 3. 魚の状態（ルール）

| 項目 | 値 |
|---|---|
| ゲージ | 0〜25。有効な世話で+1。25で満タン→結末へ |
| 腹持ち | 0〜18（企画書は9→倍増）。登場時12。通常遊泳10秒で−1（くいしんぼう×1.3、のんびり×0.7）。ふれあい成功で−1 |
| 汚れ | 0〜4段。通常遊泳90秒、糞2回、食べ残し9粒でそれぞれ+1。有効な掃除で−1 |
| ストレス | 0〜100、初期20。有効な掃除+15（ビビり+22）、きれいなガラスを磨く+5、ふれあい成功−15、そっぽ+5。きれいずきは汚れ3以上で毎秒+0.5 |
| 糞 | 累計9粒食べるごとに1回 |
| おかわり | 食べ切った後25%で欲しがる。10秒以内なら満腹でも追加9粒まで（3組）。おかわり後の再要求なし |
| 記録用 | feeds / polishes（きれいなガラスも数える）/ touches / swimTime / starveTime（腹持ち0での遊泳時間）/ fullTime（腹持ち15以上での遊泳時間）/ maxStress / netCount（生きた魚に網）/ wantsMet / combos / fishNo（何匹目、保存する） |

### 3.1 世話

- **餌**：1押しで3粒。画面に同時に18粒まで（企画書は「前の餌が残っている間は追加不可」→変更）。腹持ち＋まだ食べていない予定の粒＋3 ≤ 18 なら「食べる組」。食べる組だけ事故を抽選し、4%で金の粒が混ざる（食べるとゲージ+2）。満腹の組は首を振って食べず、底で5秒かけて消えて汚れになる。3粒食べ切るとゲージ+1。
- **掃除**：ブラシで3か所磨く。汚れがあるときだけ事故抽選。汚れを落とせたらゲージ+1。**きれいなガラスを磨いてもゲージは増えない**（企画書から変更）。
- **ふれあい**：反応（下表）を決めてから、その反応の事故だけを抽選。腹持ち0なら餌の吹き出しを出して何もしない。成功でゲージ+1。
  - 反応の重み：撫でるは `0.5`（直前が別の世話）または `1 + stress/25 + 連続回数×0.5`、のんびりは+2。芸は各1（おちょうしものは各2）。
  - 飽き：ふれあいが続くと、4回目30%→5回目50%→以降70%で**そっぽ**（ゲージ増えず、ストレス+5）。あまえんぼうは1回遅い。餌・掃除、または20秒ふれあわないとリセット。
- **網**：生きた魚はたいてい下へ逃げる（3回続けて逃げるとドヤ顔）。事故で本当にすくえてしまう。死後は魚や残ったものをすくって回収。

| 反応 | 内容（人の指つき） | 事故 |
|---|---|---|
| 撫でる pet | 指で頭をなでなで | 猫の手だった |
| ジャンプ jump | 水面に浸けた指先へ跳んでタッチ | 鳥のおやつ |
| 回転 spin | 指が円を描くとついて一回転（きっちり360°） | 回りすぎ |
| 泡 bubble | 指先から出た泡を追ってつつく | 泡と消えた |
| 膨らむ puff | お腹をつんっ→ぷくっ | 浮いたまま |
| 輪くぐり hoop | 指のOKサインの輪をくぐる | なし |
| 死んだふり deadplay | 裏返って×目→つんつん→ジャーン | なし |
| 逆立ち handstand | 底で逆立ち、尾をふりふり、指が拍手 | なし |
| ハイタッチ highfive | 跳び上がって尾で指にパチッ | なし |
| ボール ball | 指が落としたボールを鼻でリフティング | なし |
| ちゅっ kiss | 指先にキス、ハートがふわふわ | なし |

### 3.2 全部のボタンを押したくなる仕組み

- **気分ボーナス**：魚は餌・掃除・ふれあいのどれかを欲しがる（腹持ち6以下なら餌の重み+3、汚れがあれば掃除の重み1+汚れ、ストレス50以上ならふれあい+2、性格の好みは×2.5、直前と同じものは選ばない）。応えるとさらにゲージ+1（計+2）し、気分が変わる。25秒で自然に変わる。
- **コンボ**：同じボタンを続けずに3種類を一巡するとゲージ+1。虹色に光って宙返り。
- **性格**（魚ごとにランダム、登場時の名札と札に表示）：くいしんぼう／あまえんぼう／きれいずき／ビビり／のんびり／おちょうしもの。

## 4. 確率（現行値）

企画書の約2倍にしてある。`logic.js` の `P` が現行値、`P_SPEC` が企画書の値。

| きっかけ | 現行 | 企画書 |
|---|---|---|
| 登場の即死 | 8% | 5% |
| 餌の事故（食べる組ごと、5種それぞれ） | 各1%（計5%） | 各0.5% |
| 掃除の事故（有効な掃除ごと、2種それぞれ） | 各2.5%（計5%） | 各1.25% |
| ふれあいの事故（先頭5反応のみ） | 5% | 2.5% |
| 生きた魚に網 | 5% | 2.5% |
| しぐさ中の事故（6種のしぐさのみ） | 8% | （追加分）3% |
| 金の粒 | 4% | — |

- 満タン到達率（網なし・餌と掃除だけ・ボーナスなし）：理論 `(1−0.08)×0.95^25 ≈ 25.5%`（企画書の確率なら 50.45%）。気分に応え続けると約55%。
- 性格・金の粒の抽選は、企画書の確率に影響しない別の乱数（`aux`）で引く。

### 5.3 回収・札・図鑑

- 死後、右上に網のアイコン。網を押すと、網が斜め上から水に入り、獲物の下にもぐってすくい上げ、袋に入れて持ち上げる（しずくが落ちる）。漂っている途中に押したら1回だけ予約。消えた結末は空振り。
- 札：死因のミニ絵＋名前＋「N匹目　○○な金魚でした」。最初の4秒は入力無効。網で図鑑（6×6、36枠）、ほかのボタンで次へ。図鑑を閉じると同じ札に戻る。
- 次へ：泡で画面をおおい（2.6秒）、その間に水槽を全部リセット（汚れ・糞・餌・宝物・お客さん・波）してから、新しい魚が「ぽちゃん」。

## 6. 演出

### 6.1 魚

- カートゥーン調：大きな頭と短い卵形の胴、太い輪郭（#1d4d4a）、ハイライト入りの大きな目、赤いほっぺ、丸い二つ房の尾が波打つ。幅は尾まで約48px（水槽幅の約1/3）。
- 成長で体形が変わる：ゲージ0〜8は丸い幼魚、9〜17は中間、18以降はすらっとした成魚。
- 泳ぎ：カーブを描いて水槽じゅうを泳ぐ（舵を切る動き＋ひれで蹴って進む強弱）。周遊、ダッシュ、ジグザグ、大きな輪、8の字、ガラスぞいに上下、すーっと沈んでぐんと浮く、止まってきょろきょろ、泡を追う、水面をのぞく、底をつつく、をランダムに。
- 振り返り：横顔が細くなる→正面顔→反対の横顔（0.24〜0.32秒）。
- つぶし・伸ばし：速いと伸び、食べる・振り返る・ぶつかるとむにっと縮んでぷるんと戻る。
- まばたき：2〜4秒ごと、ときどき二度。
- もぐもぐ：ぱくっ（口を丸く）→ほっぺをふくらませて0.75秒噛む→ごっくん。噛んでいる間は次の粒を食べないが泳いで向かう。
- 餌：粒は速めに落ち、魚は真ん中（y≈105）まで落ちるのを下で見上げて待ってから食いつく。壁ぎわの粒には反対側から回り込み、届かなければ吸い寄せる。
- ふだんの表情：腹ぺこ＝涙目とがらせ口、ストレス高＝半目で怒り眉、汚れ＝横目、ごきげん＝ほっぺ赤。
- 吹き出し（絵だけ）：いま欲しい世話（餌／汚れ／ハート）を数秒ごとに。

### 6.2 ひまなときのしぐさ（20種＋お客さん）

14〜26秒ごとに65%で発生（世話の後8〜14秒は出ない、同じものは続けない）。状態と性格で出やすさが変わる。世話を押すとすぐやめる。

- ふつう：こっちを見る、大あくび、しゃっくり※、くしゃみ※（汚れで増）、泡ぷくぷく、しっぽ追い※、ガラスにごつん※、水草かじり、うたた寝※（満腹で増）、ごきげんダンス（低ストレスで増）、のぞきこむ※、ドヤ宙返り、あっかんべー、おなかすいた（腹ぺこで増）、そわそわ（高ストレスで増）
- 画面下：砂掘り（50%で宝物＝コイン・貝殻・ヒトデ・王冠が底に残る、最大10個）、小石の模様替え、泡のエレベーター（エアストーンの泡の柱に乗る）、砂にもぐる、ごろごろ
- ※印の6種は、8%で突然死（5.1の下6行）
- お客さん（35〜60秒ごと）：ガラスを這う巻貝（のぞくと殻にひっこむ）、砂の上のカニ（近づくとチョキン、魚は涙目で逃げる）、跳ねるエビ（追いかける）

### 6.3 水・泡・ごほうび

- 水面の波：1次元のばねで水面の高さを計算。魚が入る、指・網・猫の手・ノズルが水に出入りする、餌が落ちる、ジャンプするたびに、へこみ・盛り上がり＋横長の波紋の輪（1〜3重）＋しぶき＋「ちゃぽん」。
- 起動時と次の魚の前：大小400個の泡が下から湧いて白く画面を満たし、はじけて晴れる。
- エアストーン：底に常にあり、泡の柱が出続ける。
- ごほうび演出：3粒食べ切るたび「おいしい」顔とハート、満腹近くで満足顔。汚れが落ちるとキラキラ目で一周。きれいなのに磨くと「？」の横目。気分ボーナスで「きぶん +1」、コンボで「コンボ！ +1」と虹、金の粒で「きんのつぶ！ +2」。

## 7. 音（WebAudio で合成）

- 効果音：ぽちゃん、粒が落ちる、ぱくっ、もぐ、ごっくん、ブラシ、吸い込み、泡、はじける、ジャンプ、しぶき、ちゃぽん、なでなで、回転、膨らむ、網、ドヤ、死、感電、猫、鳥、ファンファーレ、ぷ、コトン、アヒル、札、巨大化、しゃっくり、くしゃみ、あくび、ごつん、ぼよん、いびき、ダンス、起動。
- BGM（メロディ・ベース・分散和音・キック/スネア/ハイハット、8分音符単位）：
  - main（ふだん、104BPM、C-Am-F-G）／happy（ストレス15以下・腹持ち8以上・汚れ1以下、128BPM）／tense（腹持ち2以下・汚れ最大・ストレス85以上、112BPM）／card（札、84BPM、Dm-E）
  - 遊んでいる間は3秒ごとに状態で曲を切りかえる。ぽちゃんの後2.5秒と最期の演出中は無音。死亡・ファンファーレなど大きな出来事のときだけBGMを少し下げる。
- 水音：ローパスしたノイズを小さく常に。

## 8. 絵の方針

## 9. 作り直しの進め方（おすすめ）

1. **ルール層**（描画なし、乱数を注入）：`prototype/logic.js` の API（newFish / tick / startFeed / eatPellet / finishFeed / startClean / finishClean / startTouch / finishTouch / net / gestureAccident / decideEnding / die / record / save / load / bonus など）を移植し、`test_logic.js` の121件が通ることを確認。満タン到達率のモンテカルロ（10万回）を必ず入れる。
2. **描画層**：160×240 キャンバスにスプライト。まず魚（成長3段階×表情×振り返り×つぶし伸ばし×もぐもぐ）と水槽。
3. **演出層**：ジェネレータ（`function*`）で書いた「タスク」を毎フレーム進める方式が書きやすかった（`yield 秒数` で待つ、`yield () => 条件` で条件待ち）。世話の演出、死の演出、しぐさ、お客さんをそれぞれタスクに。
4. **見本ページ**：任意の死因・芸・しぐさを強制的に再生できる「demo モード」を最初から作ると、見た目の確認がとても楽（試作の gallery.html）。
5. **音**：効果音→BGM。
6. **確認**：ヘッドレスブラウザで「12通りの乱数×12分の乱打で止まらない」耐久テスト（試作の playtest の考え方）。過去に「泡が先に消えて待ちっぱなし」「壁ぎわの餌に届かない」で止まったことがあるので、すべての待ちに逃げ道（タイムアウトか条件の消滅）をつける。

## 10. 試作で決めたこと・注意点

- 企画書から変えたもの：腹持ちと画面の粒数を9→18、餌を食べている最中に追加可、きれいなガラスを磨いてもゲージは増えない、突然死の確率を約2倍、死因を24→36種、ふれあいの芸6種と飽き、気分ボーナス・コンボ・性格・金の粒・お客さん・宝物、名前と享年は付けない（何匹目だけ出す）。
- 解釈で決めたもの（要確認）：「吸い込まれた」は汚れを落とさない／図鑑は網で開き、どのボタンでも札に戻る／前の魚と同じ結末は同じ段で重み0.5／札まで見た結末は再生し直さない／タイトル「きんぎょのさいご」は仮。
- 保存（localStorage `goldfish_v1`）：図鑑、前の結末、何匹目、進行中の魚の状態。世話の完了・結末決定・死亡・回収で保存。
- 見た目で弱いところ：結んじゃった（結び目の交差がやや分かりにくい）、昇天の羽（小さいと紙飛行機っぽい）。
- Arduino 化に向けて：画面解像度とボタン数が決まったら、描画を固定パレットのタイル／スプライトに置き換える。ルール層は描画に依存していないので、そのまま C++ に移しやすい。
